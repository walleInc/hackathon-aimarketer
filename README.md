# Автономный AI-маркетолог

Прототип для хакатона «Кибер 102»: Telegram-бот + Mini App + Core API с AI-агентом.

```
Telegram (бот, Mini App) ──► Core API (FastAPI)
                              ├─ auth: подпись initData, роли, изоляция по company_id
                              ├─ agent: LLM-провайдер (stub | openai | chatgpt_account)
                              ├─ workflow: автомат статусов согласования
                              ├─ scheduler: регулярные задачи и отложенная публикация
                              └─ platforms: telegram (vk, max — добавляются в REGISTRY)
```

## Запуск локально

```bash
cd backend
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # заполните BOT_TOKEN, ADMIN_IDS
uvicorn app.main:app --reload
```

Без `PUBLIC_URL` бот работает через long polling. С `LLM_PROVIDER=stub` внешних вызовов нет —
можно проверить весь сценарий без ключей.

Mini App: `cd frontend && npm install && npm run dev` (для входа в браузере без Telegram
задайте `VITE_DEV_USER=<id>` и `DEV_AUTH_BYPASS=true` в backend/.env — только для разработки).
Для работы внутри Telegram нужен публичный HTTPS-адрес (cloudflared/ngrok или деплой) → `PUBLIC_URL`.

Для очередей и кэша нужен Redis: `REDIS_URL=redis://localhost:6379/0` (например, `docker compose up -d redis`).
Без него всё работает в одном процессе, без повторов и отложенного запуска. Файлы контекста организаций
хранятся в Yandex Object Storage — задайте `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`
(ключи только в `.env`, в репозиторий они не попадают).

## Тесты

```bash
cd backend && .venv\Scripts\python -m pytest
```

Покрывают критерии: публикации нет без согласования, отклонённое не публикуется,
дублей нет, компании изолированы, токены не отдаются наружу.

## Подключение новой компании (без кода)

1. Откройте Mini App под администратором (ID в `ADMIN_IDS`) → «Компании» → «Создать».
2. Выберите компанию → добавьте знания (описание, продукты, аудитория).
3. «Канал для публикаций»: укажите `@channel`; бот должен быть админом канала.
4. «Приглашение» → отправьте ссылку согласующему; он переходит по ней и привязывается к компании.

## Деплой

`docker compose up -d --build` (Postgres + приложение; фронтенд собирается в образ и
отдаётся тем же сервисом). Задайте `PUBLIC_URL` — webhook ставится автоматически.

## Что не реализовано (честно)

- Подключение через аккаунт ChatGPT (`llm/chatgpt_account.py` — заготовка, критерий №12 требует проверки).
- Адаптеры VK и MAX, сбор статистики соцсетей, мониторинг комментариев, анализ конкурентов.
- Парсинг сайтов в базу знаний (файлы TXT/MD/CSV/JSON/PDF/DOCX загружаются в Yandex S3).
- Источник для очереди `moderation` (мониторинг комментариев); обработчик готов.
- Миграции БД (Alembic): таблицы создаются при старте.

### Пост по изображению-референсу

Отправьте боту одно фото (или PNG/JPEG/WebP файлом, до 10 МБ) и напишите
задание для поста в подписи. Например: «Создай пост про новую услугу.
Для картинки возьми палитру и композицию референса, замени заголовок на …».
Альбомы не поддерживаются. Референс передаётся генератору изображений через
`/v1/images/edits`; текстовая модель получает задание без изображения.
Референс не сохраняется в истории чата и не отправляется в последующих запросах.

Для API: `POST /api/agent/message/reference`, multipart-поля `text` и один файл
`reference`, с обычной авторизацией сотрудника компании.

### Статистика публикаций и рекомендации

Во вкладке «Статистика» доступны периоды 7/30/90 дней и всё время, показатели
постов, сводка и график числа публикаций по дням (МСК). Сводка использует до
200 последних публикаций периода и показывает покрытие каждого показателя.
При публикации сохраняются фактическое время и числовой ID канала.
Старые посты без известной даты доступны в периоде «Всё время»; дата создания
черновика не подменяет дату публикации.

Telegram автоматически присылает абсолютные счётчики анонимных реакций, если
бот — администратор канала. Обновление `message_reaction_count` включено для
webhook и polling. Повторы и устаревшие события не удваивают показатели.
Счётчики относятся к основному опубликованному сообщению: если изображение
и длинный текст отправлены отдельно, учитывается сообщение с текстом.
Если канал публикуется отдельным ботом, его обновления также должны поступать
в приложение; настройка токена только для отправки не подписывает основной
бот на события другого бота.

Просмотры, пересылки и комментарии администратор компании вносит из Telegram
вручную: Bot API не предоставляет чтение этих счётчиков. Неизвестное значение
показано как «—», измеренный ноль — как 0. Пустые поля при сохранении не
меняют прежние показатели. Каждое измерение содержит время и источник.

Доля реакций = реакции / просмотры × 100%, если просмотров больше нуля
и показатели измерены с разницей не более 24 часов. Общая доля — отношение
сумм по этим же постам, а не среднее процентов. Просмотры не означают уникальный
охват. Автоматические рекомендации сравнивают только посты одного канала с
известной датой и минимум 100 просмотрами, при наличии хотя бы трёх измерений.
Для корректных экспериментов собирайте счётчики через одинаковый срок после
публикации: рекомендации формулируются как гипотезы, не причинные выводы.

AI-анализ запускается администратором компании по кнопке после измерения хотя
бы трёх постов. Использует настроенную текстовую модель, до 50 последних
измеренных постов, бюджет и лимиты компании. Результат сохраняется; повтор без
изменения данных возвращает сохранённый результат без нового LLM-запроса.
При изменении данных показывается отметка об устаревании. Расписания и
публикации анализ не меняет. Оператор сервиса может просматривать статистику,
но не вносить показатели и не заказывать AI-анализ от имени клиента.

API: `GET /api/analytics/posts?days=30`, `PUT /api/posts/{id}/metrics`
(частичный JSON со счётчиками; необязательный `observed_at` с часовым поясом),
`POST /api/analytics/posts/recommendations` (`{"days":30}`).
Новые таблицы и колонки добавляются существующей мини-миграцией при старте.
